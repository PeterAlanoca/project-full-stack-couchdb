🗂️ Detalle de Entidades
🔐
Admin
db: admins
Usuarios administradores del sistema. Gestionan clientes, películas y alquileres.
  • _id PK string
  • username string
  • passwordHash string
  • fullName string
  • email string
  • role superadmin|admin
  • isActive boolean
  • createdAt datetime
  • lastLoginAt datetime?
👤
Customer
db: customers
Clientes del videoclub. Pueden estar activos o bloqueados con registro de razón.
  • _id PK string
  • dni string
  • fullName string
  • phone string
  • email string
  • birthDate date
  • address EMB object
  • status active|blocked
  • block EMB object?
  • createdBy FK → Admin
  • updatedBy FK → Admin
🎬
Movie
db: movies
Catálogo de películas. Los oscars se almacenan como array embebido.
  • _id PK string
  • title string
  • alternativeTitles EMB string[]
  • durationMinutes number
  • genres EMB string[]
  • year number
  • actors EMB string[]
  • oscars EMB Oscar[]
  • unitCostBs number
📀
Copy
db: copies
Copias físicas de películas. Registra desactivación con razón detallada.
  • _id PK string
  • movieId FK → Movie
  • copyCode string
  • status available|rented|inactive
  • acquiredAt datetime
  • deactivation EMB object?
🧾
Rental
db: rentals
Registro de alquiler. Incluye snapshot del cliente e items embebidos para preservar historial.
  • _id PK string
  • customerId FK → Customer
  • customerSnapshot EMB object
  • items EMB RentalItem[]
  • subtotal number
  • discountPercent number
  • discountAmount number
  • total number
  • status active|returned|overdue
  • rentedAt datetime
  • dueDate datetime
  • returnedAt datetime?
🔗 Relaciones
ADMIN ──→ CUSTOMER Registra y actualiza clientes (createdBy / updatedBy) 1 : N
CUSTOMER ──→ RENTAL Un cliente puede realizar múltiples alquileres (customerId) 1 : N
MOVIE ──→ COPY Una película tiene múltiples copias físicas (movieId en Copy) 1 : N
RENTAL ──→ RENTAL_ITEM Un alquiler contiene uno o más ítems (array embebido) EMBEBIDO
COPY ──→ RENTAL_ITEM Cada ítem referencia una copia específica (copyId) 1 : N
MOVIE ──→ OSCAR Los premios Oscar se almacenan embebidos dentro del documento Movie EMBEBIDO

ℹ️ Consideraciones del Modelo Documental (CouchDB)

  • No existen claves foráneas nativas. Las relaciones se implementan mediante IDs referenciados y la integridad la gestiona NestJS en la capa de aplicación.
  • Snapshots embebidos: customerSnapshot en Rental preserva el nombre/email del cliente al momento del alquiler, garantizando que el historial no cambie aunque el cliente se modifique.
  • Arrays embebidos: oscars[] en Movie y items[] en Rental evitan documentos extra y optimizan lecturas (un solo fetch).
  • Los IDs siguen el formato entidad:uuid (ej: customer:abc123) para facilitar el particionado lógico en CouchDB.
  • El campo _rev de CouchDB gestiona el control de concurrencia optimista automáticamente en cada documento.
